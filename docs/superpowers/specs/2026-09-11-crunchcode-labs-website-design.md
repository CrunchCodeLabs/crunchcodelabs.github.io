# CrunchCode Labs — Studio Website Design

**Date:** 2026-09-11
**Status:** Approved, ready for implementation planning
**Deploy target:** `https://crunchcodelabs.github.io/`

---

## 1. Context

CrunchCode Labs is an independent mobile app studio. Two apps exist today, both already
published on Google Play:

| | My Book Trail | Pure Mathematics Sinhala |
| --- | --- | --- |
| Package | `com.crunchcodelabs.mybooktrail` | `com.crunchcode.puremathematicssinhala` |
| Version | 1.30 (live) | 1.12 live, 2.0 in development |
| Category | Books & Reference | Education |
| Store assets | icon, feature graphic, 8 phone + 8 tablet panels | 512px web icon only |
| Legal pages | written (privacy 44KB, terms 24KB) | not yet written |
| Data collection | AdMob + Meta Audience Network; Google Drive `appdata` sync | none in 2.0 (ads removed, zero runtime permissions) |

There is no studio website. My Book Trail has a standalone one-page site at
`MyBookTrail/store/site/`, generated by a local `gen3.js`. That page is superseded by this
project; its privacy and terms content is migrated, not rewritten.

The two apps disagree about data collection, which is why legal pages are **per-app** rather
than studio-wide.

### 1.1 Goals

1. A studio site presenting the CrunchCode Labs brand and every app under it.
2. A per-app page carrying icon, screenshots, description, store links, and links to that
   app's privacy policy and terms.
3. Adding a future app must be a content edit, not a development task.
4. Legal pages served at stable, dedicated URLs suitable for Google Play Console.

### 1.2 Non-goals

- No CMS, admin UI, or backend.
- No blog, changelog, or newsletter in this release.
- No first-party analytics or tracking. The Buy Me a Coffee widget on `/` sets its own
  cookies (§7.3).
- No i18n framework. Sinhala appears as app content, not as a site-wide locale.
- No rewrite of the existing legal copy — it is migrated verbatim.

## 3. Visual direction

Approved direction: **Gradient Showcase**, with the **centered hero** app-page template.

- The homepage hero sits on a radial indigo mesh gradient in the studio accent.
- Each **app page** hero uses that app's *own* accent, not the studio indigo. This is what
  keeps a gradient-heavy design from making every app page look identical.
- App cards on the homepage take a coloured header band derived from the same per-app accent.
- Store badges appear above the fold on both the homepage and every app page.

Per-app accents:

| App | Accent | Source |
| --- | --- | --- |
| My Book Trail | `#0C7C81` teal, deep `#053C40` | sampled from the shipped Play icon |
| Pure Mathematics Sinhala | `#16E5A4` green, deep `#075C42` | sampled from `ic_launcher-web.png` |

## 4. Information architecture

```
/                                  Studio homepage — hero + app grid
/apps/<slug>/                      App detail page
/apps/<slug>/privacy/              App privacy policy   ← Play Console target
/apps/<slug>/terms/                App terms & conditions
/about/                            The studio
/support/                          Contact + per-app support routing
/404.html
/sitemap-index.xml, /robots.txt
```

There is deliberately no `/apps/` index page. With two apps the homepage grid *is* the index;
a separate listing page would be an empty room. The trigger to add one is **seven apps** —
see §10.

## 5. Content model

This section is the answer to "easily scalable for new coming apps". Everything else in the
site is generated from it.

### 5.1 Layout

```
src/content/apps/
  my-book-trail.md
  pure-mathematics-sinhala.md
src/content/legal/
  my-book-trail-privacy.md
  my-book-trail-terms.md
  pure-mathematics-sinhala-privacy.md
  pure-mathematics-sinhala-terms.md
public/apps/my-book-trail/
  icon.png
  feature.png
  screens/01-your-library.png … 08-safe-portable.png
  screens-tablet/01-your-library.png … 08-safe-portable.png
```

### 5.2 Schema

Enforced by Astro content collections with Zod. A missing or malformed required field
**fails the build** rather than shipping a broken page.

```ts
{
  slug:        string            // URL segment, also the asset folder name
  name:        string            // "My Book Trail"
  nativeName?: string            // "ශුද්ධ ගණිතය සූත්‍ර" — rendered in Noto Sans Sinhala
  tagline:     string            // one line, hero subtitle
  category:    string            // "Books & Reference"
  status:      'live' | 'beta' | 'coming-soon'
  badge?:      string            // free text chip, e.g. "2.0 in development"
  order:       number            // homepage grid position
  accent:      string            // hex, drives hero gradient + card header
  accentDeep:  string            // hex, gradient terminus
  packageId:   string
  version:     string
  platforms:   ('android' | 'ios')[]
  playUrl?:    string            // required when status === 'live'
  appStoreUrl?: string
  icon:        string            // path under public/apps/<slug>/
  feature?:    string
  screenshots:      string[]     // may be empty — see §6.3
  screenshotsTablet?: string[]
  features:    { title: string; body: string }[]   // 3–6 items
  support:     { email: string; donate?: string }
  privacy?:    string            // legal collection ref
  terms?:      string
}
```

The markdown **body** is the long-form "About" description.

### 5.3 Adding an app — the runbook

1. `src/content/apps/<slug>.md` — fill the frontmatter above, write the body.
2. `public/apps/<slug>/` — drop in `icon.png` and `screens/`.
3. `src/content/legal/<slug>-privacy.md` and `<slug>-terms.md`.
4. `npm run build`.

Homepage card, detail page, both legal pages, routes, sitemap entries and OG image are all
derived. No component, route, or config file is touched.

## 6. Page designs

### 6.1 Homepage

Indigo mesh gradient hero: nav, `Apps that feel good to use.`-class headline, studio
sub-line, Play/App Store badges, and two tilted device mockups built in CSS (not
screenshots — these are decorative and must not depend on any app's assets).

Below: the app grid. Cards carry a coloured header band in the app's accent with the icon
centred, then name, category, status chip, and a `View app` action.

**Grid sizing:** `repeat(auto-fit, minmax(280px, 1fr))` with `max-width` capping the row at
three columns. With two apps this yields two comfortably-sized cards rather than two
stranded cards in a four-wide row.

### 6.2 App detail page

Order of blocks, top to bottom:

1. **Hero** on the app's own accent gradient — breadcrumb, large icon, name
   (plus `nativeName` beneath it where present), tagline, metadata chips
   (category · platforms · version · price), store badges.
2. **Screenshot rail** — see §6.3.
3. **About** — markdown body, then a 3-column feature grid.
4. **Legal** — two cards linking to the privacy and terms pages, each showing its URL.
5. **Footer** — studio wordmark, tagline, contact.

### 6.3 Screenshots

**Decision: reuse the existing `out/` marketing panels as-is.** They already contain device
frame, caption and background, so the site must **not** wrap them in further device chrome —
that would double-frame them.

Consequences accepted:

- The rail band is a **neutral light grey**, not the indigo tint from the mockup. A tinted
  band would fight My Book Trail's dark-green panels.
- Each app's rail carries that app's own panel styling. Cross-app consistency is traded for
  reuse of work already done, as chosen.
- Panels render at their natural 9:16 in a horizontally scrolling rail with scroll-snap,
  keyboard arrow support, and `overflow-x: auto` confined to the rail — the page body never
  scrolls sideways.
- `screenshotsTablet` feeds a `srcset` at wide viewports where present.

**Empty state:** when `screenshots` is empty — Pure Mathematics Sinhala today — the rail is
replaced by the app's feature graphic if present, otherwise omitted entirely. The section
header is not rendered. A page with no screenshots must look finished, not broken.

### 6.4 Legal pages

Minimal document layout: studio nav, app name + document title, last-updated date, sticky
table of contents on desktop, body copy at `max-width: 68ch`. No gradient, no marketing.
The policy is the page's primary content — this is what Play Console expects.

Content is migrated from `MyBookTrail/store/site/privacy-policy.html` and `terms.html`,
converted to markdown, **wording unchanged**. Pure Mathematics Sinhala's pair must be
written fresh and must state zero data collection for 2.0; until then its page renders the
1.12 reality. See §11.

### 6.5 About and Support

`/about` — the studio, the `// build · ship · iterate` idea, contact.
`/support` — per-app support routing to `crunchcodelabs@gmail.com`, plus the existing
`buymeacoffee.com/crunchcodelabs` link.

## 7. Technical approach

**Astro, static output.** Chosen for content collections — the schema in §5.2 is the
scalability requirement expressed directly in the tool — plus build-time image optimization,
which matters because the screenshot set is 3.8MB of unoptimized PNG today.

Rejected: hand-written HTML in the style of `store/site/` (does not survive past ~3 apps
without copy-paste drift); Next.js (a server runtime that would never be used).

- Astro 7, TypeScript strict. The only client JS is the third-party Buy Me a Coffee
  widget on `/` (§7.3); the screenshot rail uses native scroll-container keyboard
  behaviour and ships no JS of its own.
- `@astrojs/sitemap`; `astro:assets` → WebP with responsive `srcset`, lazy below the fold.
- No CSS framework. Design tokens as CSS custom properties, per-app accent injected as
  inline custom properties on the page root.
- Two CDN dependencies, both Buy Me a Coffee and both confined to `/` and `/support`
  (§7.3). No legal page loads third-party code.

### 7.3 Donations

Buy Me a Coffee appears in two forms, each on exactly one page:

| Page | Form | Loads |
| --- | --- | --- |
| `/` | Floating widget, bottom right | `cdnjs.buymeacoffee.com/1.0.0/widget.prod.min.js` |
| `/support` | Official yellow button, inline under **Support the work** | `cdn.buymeacoffee.com/buttons/v2/default-yellow.png` |

The widget cannot be placed inline — `data-position` only chooses a corner — which is why
the support page uses the button image instead. The script tag carries `is:inline`: Astro
would otherwise bundle it and strip the `data-*` attributes it reads its configuration
from, leaving it to load and silently do nothing.

These are the site's only external runtime dependencies and its only client-side
JavaScript, and they are a deliberate exception to §1.2 and §7. **No legal page loads
either**, which is checked on every build — a privacy policy that itself pulls in
third-party code is a poor look under Play review.

### 7.1 Repository

New repository, root of `F:\Workspace\AndroidApps\CrunchCodeLabs`. `.gitignore` must cover
`node_modules/`, `dist/`, `.astro/`, and `.superpowers/`.

Brand assets already present at the repo root (`crucnhcodelabs_logo.svg|png`,
`crucnhcodelabs_banner.svg|png`) move to `src/assets/brand/`. **Filenames retain the existing
`crucnh` misspelling** unless renamed deliberately — they are referenced as-is today.

### 7.2 Deployment

GitHub organization `crunchcodelabs`, repository `crunchcodelabs.github.io`, served from the
root — **no base path**. GitHub Actions builds on push to `main` and publishes `dist/`.

`astro.config.mjs` sets `site: 'https://crunchcodelabs.github.io'` and no `base`. Moving to
`crunchcodelabs.com` later is a `CNAME` file plus a one-line `site` change; every path in
§4 stays valid.

## 8. Accessibility and performance

- Colour contrast ≥ 4.5:1 for body text. Hero text over gradient is verified per app accent,
  not assumed — a light accent may require the ink treatment instead of white.
- Every image has meaningful `alt`; screenshot alt text comes from the panel's caption.
- Visible focus rings in `--accent`; the screenshot rail is keyboard-navigable.
- `prefers-reduced-motion` disables gradient animation and scroll-snap smoothing.
- Semantic landmarks, one `h1` per page, skip-to-content link.
- Budget: ≤ 120KB of non-image transfer per page; LCP image preloaded.
- Responsive from 320px. Wide content scrolls inside its own container, never the body.

## 9. Error handling and failure modes

| Failure | Behaviour |
| --- | --- |
| Required schema field missing | Build fails with the file and field named |
| `status: 'live'` without `playUrl` | Build fails |
| Referenced image absent | Build fails |
| `screenshots` empty | Rail section omitted (§6.3) |
| `privacy`/`terms` unset | Legal card omitted; no dead link rendered |
| `nativeName` absent | Native-name line omitted |
| App Store URL absent | Only the Play badge renders |

The principle: an incomplete app entry either fails loudly at build time or degrades to a
page that still looks finished. It never ships a broken link.

## 11. Open items requiring the owner

These do not block implementation but must be resolved before the site is authoritative.

1. **Play Console privacy URL for My Book Trail.** A privacy policy URL is already submitted
   to Play, and its current location is not recorded anywhere in the repository. Once this
   site is live, Play Console must be updated to
   `https://crunchcodelabs.github.io/apps/my-book-trail/privacy/`. If the existing URL is
   taken down before Play is updated, the listing is out of compliance. **Owner action.**
2. **Pure Mathematics Sinhala legal copy.** Must be written. 2.0 removes ads and all runtime
   permissions, so it is a genuinely different document from My Book Trail's.
3. ~~Pure Mathematics Sinhala accent colour~~ — resolved: `#16E5A4` / `#075C42`, sampled from the launcher icon.
4. **Pure Mathematics Sinhala store screenshots** — none exist. The page ships with the
   empty state (§6.3) until they do.
5. **Play listing URL for Pure Mathematics Sinhala** — needs confirming against the live
   listing rather than constructed from the package id.
6. **`crunchcodelabs.com`** — not owned today. §7.2 keeps the migration cheap.

## 12. Acceptance criteria

1. `npm run build` produces a static site with no errors and no broken internal links.
2. Both apps have a detail page with correct metadata and a working Play link.
3. My Book Trail's privacy and terms resolve at the §4 URLs, carrying the migrated copy
   with wording unchanged.
4. Pure Mathematics Sinhala's page renders correctly with no screenshots, and its Sinhala
   name renders in Noto Sans Sinhala without tofu.
5. Adding a third app requires touching only `src/content/` and `public/apps/`.
6. Lighthouse ≥ 95 for Performance and 100 for Accessibility on homepage and one app page.
7. The site is legible and correctly laid out at 320px, 768px and 1440px.
